## P0

### P0-1

- **Status / 状态**: Open
- **Where / 位置**: `src/Compiler.php:596,608,791`
- **Verification / 验证**: reproduced (`php -l`)
- **EN**: The loop-variable regex `^[A-Za-z_][A-Za-z0-9_]*$` lets PHP reserved variables through. `as: this` compiles to `foreach ($u ?? [] as $this):`, and `php -l` reports `Fatal error: Cannot re-assign $this`; `as: GLOBALS` produces equally unrunnable code. This breaks the invariant `spec.md` states for itself, that the artefact must be parseable PHP
- **中文**: 循环变量名校验正则 `^[A-Za-z_][A-Za-z0-9_]*$` 放行 PHP 保留变量。实测 `as: this` 编译出 `foreach ($u ?? [] as $this):`，`php -l` 报 `Fatal error: Cannot re-assign $this`；`as: GLOBALS` 同样产出不可运行代码。这直接违反 `spec.md` 自述的「产物必须是可解析的 PHP」

## P1

### P1-1

- **Status / 状态**: Open
- **Where / 位置**: `src/Compiler.php:557,620,655-661,700,764` vs `:384-403`
- **Verification / 验证**: reproduced
- **EN**: Several literal attributes are never HTML-escaped, only run through `interpolate()`: `link`'s href/target/text, `form`'s action, `field`'s name/label/id, the submit value and `option`'s value. `href = 'x" onclick="alert(1)'` produced `<a href="x" onclick="alert(1)">`, and an ordinary label containing a quote yields broken HTML. Meanwhile `el`'s pass-through attributes do go through `htmlspecialchars`, so one compiler has two standards
- **中文**: 部分字面量属性不做 HTML 转义，只过 `interpolate()`：`link` 的 href/target/text、`form` 的 action、`field` 的 name/label/id、submit 的 value、`option` 的 value。实测 `href = 'x" onclick="alert(1)'` → `<a href="x" onclick="alert(1)">`；含引号的普通 label 也会产出坏 HTML。而 `el` 的透传属性走 `htmlspecialchars`，同一编译器两套标准

## P2

### P2-1

- **Status / 状态**: Open
- **Where / 位置**: `src/Compiler.php:199-218,229-248,402`
- **Verification / 验证**: reproduced
- **EN**: Pass-through attribute names are not validated character by character: `isForwardable()` only checks prefixes and colons and `mapAttributeName()` checks nothing. `data-x"y`, `data-x y` and `x-on: y` all reach the artefact (the XML front end has `ATTR_NAME_PATTERN`, the array DSL and YAML have nothing, so the two front ends disagree)
- **中文**: 透传属性名不校验字符集：`isForwardable()` 只按前缀/冒号放行，`mapAttributeName()` 不查字符。实测 `data-x"y`、`data-x y`、`x-on: y` 都能进入产物（XML 前端有 `ATTR_NAME_PATTERN`，数组 DSL 与 YAML 没有，双前端不一致）

### P2-2

- **Status / 状态**: Open
- **Where / 位置**: `src/Renderer.php:35-39,54` vs `src/Compiler.php:1221`
- **Verification / 验证**: reproduced
- **EN**: `Renderer::$cacheDir` only rejects a value that is empty after trimming, so a path containing NUL bytes throws an uncaught `ValueError` from `mkdir()` — while `Compiler::assertTemplateName()` explicitly rejects NUL, which is self-contradictory
- **中文**: `Renderer::$cacheDir` 只挡住「trim 后为空」，含 NUL 的路径会在 `mkdir()` 抛未捕获 `ValueError`，而 `Compiler::assertTemplateName()` 明确拒绝 NUL，前后矛盾
